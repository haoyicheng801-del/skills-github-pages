# GIT 分布式版本控制工具
### 1. 概述
#### 1.1 版本控制器的方式
1. 集中式版本控制工具
    - 版本库是集中存放在中央服务器中的, team中的每个人work时从中央服务器下载代码, 是必须联网才能工作的, 局域网或互联网, 个人修改后提交到中央版本库
    - 例如: SVN与CVS
2. 分布式版本控制工具
    - 每个人的电脑上都是一个完整的版本库, 这样工作的时候就无需联网, 多人协作只需要各自的修改推送给对方, 就能看到对方的修改了
    - 例如: Git

- 开发人员之间互相`pull`或`push`也没问题

### 3. 基础操作指令

---

> **Git 工作目录**： 本地仓库中非git目录

Git工作目录下对于文件的修改会存在几个状态, 这些修改的状态会随着我们执行Git的命令而发生变化

![image-20260309180813761](C:\Users\Lenovo\AppData\Roaming\Typora\typora-user-images\image-20260309180813761.png)

1. 添加工作区到暂存区
   - `git add 单个文件名/通配符`(通配符"."将所有修改加入暂存区)
2. 添加暂存区到本地仓库
   - 提交残存去内容到本地仓库的当前分支
   - `git commit -m "注释内容"`
3. 查看修改的状态
   - `git status`

4. 查看提交日志(log)
   - `git log [option]`
   - options
     - --all 显示所有分支
     - --pretty=online 将提交信息显示为一行
     - --abbrev-commit 是的输出的commit更加简短
     - --graph 以图的形式显示

5. 版本回退
   - 最用: 版本切换
   - `git reset -- hard commitID`

6. 添加文件至忽略列表
   - 使用".gitignore"文件

### 4. 分支

可以把工作从开发主线上分离开进行操作, 避免影响开发主线

1. 查看本地分支: `git branch`

> Head 指向当前分支

2. 创建本地分支: `git branch [文件名]`
3. 切换分支: `git checkout [分支名]`
   - 可以直接切换到一个不存在的分支(创建并切换): `git checkout -b [分支名]`
4. ==合并分支==: `git merge [分支名]`
   - 一般都是将分支合并到`master`, 首先切换到`master`
   - 将一个分支上的提交合并到另一个分支
5. 删除分支: `git branch -d [分支名]`, 需要做各种检查
   - **不能删除当前分支, 只能删除其他分支**
   - `git branch -D [分支名]`

#### 分支冲突

> 若有两个user改了同一个代码, 那么合并时会造成冲突, 则提交给用户解决冲突

#### 开发中分支使用原则与流程

- master (生产分支)
- develop (开发分支)
  - 所以开发的代码都应该提交到develop分支上
- feature
  - 从develop创建的分支, 一般是同期并行开发, 但是不同期上线时创建的分支, 分支上的研发任务完成后合并到develop分支
- hotfix分支
  - 一般作为线上bug修复使用

> git快进模式: 当进行`git merge`或`git pull`时, 不会创建新的合并提交, 而是直接将当前分支的指针向前移动到目标分支的最新提交
